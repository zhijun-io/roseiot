# IoT 管理平台 PRD

## 概述

### 问题陈述

企业内部员工目前没有统一的设备管理平台。设备接入、状态查看、告警处理、远程控制和资产信息管理需要由一套内部平台支持。员工当前具体如何完成这些工作、主要困难是什么，尚待内部流程盘点和员工访谈确认。

### 方案摘要

建设供企业内部员工使用、支持私有化部署的 IoT 管理平台，并自建 MQTT broker。平台提供产品与物模型、设备资产、设备监控、告警处理和远程控制能力。平台定位为贴合内部工作流、物模型治理和私有化要求的产品，不以功能全面超过国内云厂商为目标。

### 目标用户

- **平台管理员：** 管理平台用户、角色、产品、物模型和运行配置。
- **设备运维人员：** 接入和维护设备，查看状态与历史数据，处理告警并执行授权的远程操作。
- **只读使用者：** 查看有权访问的设备、数据和告警。
- **平台运维人员：** 在企业私有环境部署、监控、备份和恢复平台及 MQTT broker。

以上角色是首期建议模型，具体组织和身份认证方式待确认。

## 目标与成功指标

### 目标

1. 为内部员工提供统一的设备管理入口。
2. 支持自建 MQTT broker 下的设备接入和运行监控。
3. 通过产品和物模型统一描述设备资产、属性、事件和服务。
4. 支持告警分派、远程控制、接入诊断和私有化运维。
5. 支持网关与子设备管理、设备软件版本维护和内部系统集成。

### 成功指标

首期目标规模为 **1,000 台设备**，遥测数据保留 **6 个月**。平均消息频率、峰值消息量和同时在线比例待盘点，需在设计容量和存储方案前补齐。

试点期间记录以下基线，基线确定后再设目标值：

| 指标 | 基线 | 目标 | 时间范围 |
|---|---|---|---|
| 设备接入成功率与平均接入耗时 | 待试点测量 | 待定 | 试点阶段 |
| 设备状态数据可见率与数据延迟 | 待试点测量 | 待定 | 试点阶段 |
| 告警确认与处理耗时 | 待试点测量 | 待定 | 试点阶段 |
| 远程控制成功率及失败原因分布 | 待试点测量 | 待定 | 试点阶段 |
| 员工完成设备管理任务的反馈 | 待收集 | 待定 | 试点阶段 |

### 非目标

- 提供面向外部客户的多租户 SaaS 产品或计费能力。
- 首期支持所有厂商专有物模型格式、Topic 和设备通信协议。
- 提供复杂规则编排或移动端应用。
- 复刻国内云厂商的全部功能或生态服务。

## 范围

### 范围内

- 自建 MQTT broker 和平台自有、带版本的 MQTT 消息约定。
- 产品管理和平台原生物模型：属性、事件、服务。
- 设备注册、启用、停用、注销、分组和凭据管理。
- 设备在线状态、最近上报时间、物模型属性及历史遥测查看。
- 遥测数据查询与 CSV 导出，目标保留期为 6 个月。
- 设备离线状态查看和期望属性记录；重连后同步物模型定义的配置属性。
- 基础告警规则、告警列表、确认、关闭、处理记录和通知。
- 告警负责人分派、按严重级别配置处理时限和逾期状态。
- 对在线设备执行授权的远程控制，记录操作者、请求、结果和时间。
- 设备接入诊断，包括认证失败、连接断开和消息/物模型校验失败记录。
- 物模型版本记录、发布和变更影响提示。
- 面向内部系统的服务端 API，用于查询设备、物模型、遥测和告警，并调用授权的设备操作。
- 网关与子设备管理；首期协议范围在设计阶段按实际设备确认。
- OTA 固件/软件包管理、按设备或分组发布，以及设备上报升级状态。
- 基础员工角色权限、重要操作审计、设备与产品批量导入导出。
- broker 运维监控、平台备份与恢复、私有化部署。

### 范围外

- 离线时排队补发任意远程命令。
- 默认实现厂商专有 MQTT Topic 或消息协议的兼容。
- 高级告警升级策略、复杂事件关联和低代码规则编排。
- 可由用户任意编排的仪表盘编辑器；首期提供固定的设备和运维视图。

### 后续考虑

- 按设备来源增加阿里云 TSL、腾讯云物模型等格式导入/导出适配器。
- 评估 W3C WoT Thing Description 作为模型交换格式。
- Modbus、OPC-UA、BLE 等额外网关协议连接器、复杂事件关联、低代码规则和移动端应用。

### 完整平台的其他能力缺口（候选项，尚未纳入范围）

要达到可长期生产运营的完整平台，还需评估以下能力。它们尚未作为已批准需求，不自动进入当前交付范围：

- **组织、站点与资源权限：** 按部门、工厂、站点或区域组织设备，并把角色权限限定到相应设备组。
- **身份与设备安全：** 员工 SSO/MFA、设备 TLS/mTLS、设备级 Topic ACL、凭据轮换和吊销、密钥安全存储。
- **生产级可用性：** broker 与平台的集群/故障转移、升级策略、容量告警、灾难恢复和恢复演练。
- **数据处理：** 数据转换、单位归一化、计算属性、规则链、异常值处理和可观测的失败重试。
- **可配置可视化：** 员工自定义仪表盘、图表、设备对比和告警概览；首期先使用固定视图。
- **告警运营：** 多渠道通知、升级/值班策略、去重/抑制、维护窗口和告警统计。
- **集成生态：** Webhook、事件订阅、数据导出到内部数据平台、目录/身份系统集成。
- **设备互操作：** 基于实际存量设备增加非 MQTT 接入、协议网关和厂商模型格式适配。
- **OTA 安全与治理：** 软件包签名/校验、兼容性限制、灰度策略、暂停/回滚及升级审计。

建议在面向生产环境开放前，优先明确身份与设备安全、部署高可用/灾难恢复，以及 OTA 安全边界；其余能力按员工使用需求和设备类型分批规划。

### 用户体验

- 首期以设备列表、设备详情、产品/物模型管理、告警处理和运维状态视图为主要工作入口。
- 设备详情应能查看基本资产信息、连接状态、当前属性、历史数据、告警和审计记录。
- 远程操作应在提交前展示目标设备和调用服务，并在提交后展示回执或失败原因。
- 固定运维视图优先；通用仪表盘编辑器作为后续候选。

### 边界情况

| 场景 | 预期行为 |
|---|---|
| 设备离线时员工发送远程服务调用 | 拒绝发送或标记未执行并解释原因；不得静默排队执行。 |
| 离线设备期望属性多次变更 | 保留最新期望值及变更记录；重连时同步最新值并记录设备确认结果。 |
| 设备上报属性不符合物模型 | 拒绝或隔离该数据，记录校验失败原因，不将其作为有效物模型数据展示。 |
| 邮件服务不可用 | 告警仍保存在平台并显示通知失败状态，支持后续重试或人工查看。 |
| 备份恢复失败或数据不完整 | 明确报告恢复结果和失败对象，不显示为恢复成功。 |

## 技术注意事项

### 约束

- 已确认：自建 MQTT broker、MQTT 接入、私有化部署、目标设备规模 1,000 台、遥测保留 6 个月。
- 首期消息约定建议为平台自有且带版本号的 JSON 格式；协议细节在 `sdd-design` 阶段确定。
- 设备平均消息频率、峰值并发、报文大小和同时在线比例尚未提供。设计阶段应按设备清单计算容量和存储需求；1,000 台设备和六个月保留期本身不足以确定资源规格。
- 目标部署系统、容器编排、离线安装、身份认证集成和 SMTP 服务仍待内部运维确认。
- 不在 PRD 预先规定具体数据库、框架、服务拆分或部署拓扑。

### 集成点

- MQTT 设备端与自建 broker。
- 企业邮件 SMTP 服务。
- 内部系统通过平台服务端 API 集成；首期不依赖公有云 API。
- OTA 固件/软件包的文件存储和设备升级结果上报；具体存储方案在设计阶段确定。

### 数据要求

- 遥测数据保留期：六个月。
- 告警和审计记录的正式保留期限需结合企业制度确认；建议首期至少保留一年。
- 备份建议每日执行并保留 30 天；恢复演练至少每季度一次，建议目标 RPO 24 小时、RTO 8 小时。
- 以上告警/审计保留和备份目标为建议值，不是已确认的企业政策。

| 六个月遥测保留的存储需求因消息频率和报文大小而显著变化 | 中 | 高 | 在设计前盘点消息频率、数据大小和峰值，建立存储容量模型。 |
| 设备固件使用不统一的消息格式 | 中 | 高 | 定义版本化平台消息约定；通过适配器逐步兼容已确认的设备格式。 |
| 物模型变更导致设备端、平台和历史数据语义不一致 | 中 | 中 | 在详细设计中确定模型版本和兼容规则；物模型发布需有影响提示。 |
| 远程控制误操作影响设备运行 | 中 | 高 | 采用角色授权、操作确认、审计和设备响应状态。 |

## 待确认问题

- 1,000 台设备中预计同时在线比例、平均上报周期、峰值消息速率和典型报文大小是多少？
- 网关首期要接入哪些实际设备和子设备标识？是否只需 MQTT 网关，还是需要其他协议连接器？
- OTA 设备端支持何种升级流程、包格式、签名校验和失败恢复？是否需要灰度批次或回滚？
- 是否有非 JSON 或厂商专有消息格式需要首期接入？
- 物模型版本发布后，旧版本设备如何兼容？破坏性变更是否需要阻止发布？
- 内部系统 API 的调用方、身份认证方式、权限粒度和服务等级是什么？
- 私有环境是容器主机还是 Kubernetes？是否要求无互联网安装？
- 企业员工身份是否接入现有 LDAP/SSO？角色权限是否还需按部门、区域或设备组隔离？
- 告警通知邮件收件人如何确定，是否需要企业微信/钉钉等渠道？
- 告警和审计记录保留一年是否符合内部政策？
- 备份目标 RPO 24 小时、RTO 8 小时，以及每日备份保留 30 天是否可接受？
- 设备清单、当前人工流程和试点目标由谁提供？
