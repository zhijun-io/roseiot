# Roseiot 产品需求文档（PRD）

## 1. 概述

Roseiot 是面向跨行业 IoT 平台运营方与租户的多租户平台，目标是让平台运营者和租户在统一平台管理设备、数据、操作与告警。

本 PRD 描述 Roseiot 的整体产品方向和分阶段能力，不替代模块级 Spec。当前阶段 0 工程基线已完成；阶段 1 管理模块尚未实现，是当前规划的交付重点。后续阶段依次规划 IoT、通知和 AI 模块。

产品需求先在本 PRD 中确认，再据此创建和评审模块 Spec。阶段 1 已有[管理模块 Spec（GitHub Issue #9）](https://github.com/zhijun-io/roseiot/issues/9)，它记录了此前整理的详细方案；应与本 PRD 对齐，不能反过来替代产品需求。若两者存在产品范围差异，应先确认并更新相关文档。

## 2. 问题陈述

Roseiot 要解决的核心问题是：跨行业的 IoT 平台运营方和租户需要在多租户边界内管理设备、设备数据、远程操作及异常告警。具体行业现状、现有工具造成的损耗及其用户研究证据尚未提供，当前问题描述代表已确认的产品目标，仍需通过实际用户验证。

## 3. 目标与愿景

提供一个支持多个相互隔离租户的 IoT 平台，使平台运营方能管理平台和租户，租户能管理自身成员及 IoT 业务；逐步形成从设备管理、数据查看、设备操作到异常处理的连贯工作流。

平台能力按阶段扩展。通知能力围绕已识别的业务告警交付；AI 能力须在使用场景、数据条件和预期收益明确后再定义。

## 4. 目标用户

- **平台运营方**：负责平台准入、租户、平台管理能力和运行策略。
- **租户管理员**：负责本租户成员、访问权限及本租户 IoT 资源。
- **租户业务用户**：依据获授权限查看设备和数据、执行获准操作及处理告警。
- **设备使用方**：使用平台了解设备状态、数据和操作结果；其具体行业角色尚未细分。

首批目标覆盖跨行业场景；具体行业、设备规模和典型业务流程尚待验证。

## 5. 关键产品能力与用户用例（本次范围）

**阶段 1 · 管理模块（当前规划，尚未实现）**

- **平台启动与管理员准入**：不开放公开注册；通过受控的一次性初始化流程建立首个平台管理员，并要求其首次登录后更改临时密码。
- **身份认证与登录方式**：支持平台启用的密码认证和外部 OIDC 登录；登录失败响应避免泄露账户是否存在。
- **个人账户安全**：用户可管理个人资料、验证并更改邮箱、修改或恢复密码、申请注销账户、查看和撤销会话、管理已开放的 MFA 因子及关联的外部身份。
- **租户与成员**：平台运营方创建和管理租户；租户用户通过邮件邀请加入，接受邀请时设置密码；邀请可附带零个或多个当前租户角色。无角色用户仅能使用个人账户能力和明确开放的公开功能。
- **角色与访问控制**：平台与租户管理员按各自权限管理角色；角色组合可授权操作，平台权限与租户权限分开，平台身份本身不授予客户业务数据访问权。
- **管理资源目录**：统一维护平台和租户范围内的分组、菜单与按钮操作资源；操作权限由服务端校验。
- **系统认证与平台设置**：平台运营方配置通用设置、登录与会话安全策略、密码策略、邮件发送、MFA 方法和基于模板配置的 OIDC 提供商及用户属性映射。
- **管理追溯**：获授权人员查询管理审计和认证事件，包括未能对应到已知用户的认证尝试。

阶段 1 内部按垂直切片交付，并在本阶段完成可靠性、性能和部署验证。具体业务流程、API、模型约束与验收边界由 Issue #9 管理模块 Spec 维护。

**阶段 1 主要用户用例（按角色）**

**部署负责人**

- 作为部署负责人，我希望受控地建立首个平台管理员并要求其首次登录后更改临时密码，以便安全启动平台。

**平台管理员**

- 作为平台管理员，我希望创建、停用和恢复租户，并设定租户可用的管理能力，以便维护租户边界和管理权限上限。
- 作为平台管理员，我希望维护平台管理角色与资源，并配置登录、安全、邮件、MFA 和 OIDC 能力，以便按部署需要管理平台。
- 作为平台管理员，我希望查看获授权范围内的管理审计，以便追溯重要管理操作。

**租户管理员**

- 作为租户管理员，我希望通过邮件邀请成员并可选择分配本租户角色，以便受控地为团队开通访问。
- 作为租户管理员，我希望管理本租户成员、角色及其权限，并遵守平台设定的权限范围，以便按职责维护团队访问。

**受邀用户**

- 作为受邀用户，我希望通过邮箱邀请完成账户激活并设置密码，以便安全加入租户。
- 作为未分配角色的用户，我希望仍能登录并管理自己的账户，以便在获授管理权限前使用个人账户功能。

**平台用户与租户用户**

- 作为用户，我希望使用已开放的密码或 OIDC 方式登录，并管理自己的资料、邮箱、密码、会话、MFA 与外部身份，以便维护账户安全和可访问性。
- 作为获授权用户，我希望只能执行所属角色所授予的操作，以便平台和租户数据按权限边界受到保护。

**获授权的安全管理员**

- 作为安全管理员，我希望查询认证成功和失败事件，包括无法对应到已知用户的尝试，以便调查认证问题和潜在攻击。

**后续阶段能力（规划方向，不是当前交付承诺）**

- **阶段 2 · IoT 模块**：产品与设备管理、设备数据查看、设备操作与反馈、规则和告警。
- **阶段 3 · 通知模块**：从 IoT 告警触发 Webhook 通知开始，后续通道按需求决定。
- **阶段 4 · AI 模块**：AI 相关能力待场景、数据条件与收益目标明确后定义。

**后续阶段主要用户用例（规划）**

**阶段 2 · IoT 模块**

- 作为租户管理员，我希望管理产品、登记和维护设备，并定义设备数据与命令能力，以便建立和维护本租户的设备资产。
- 作为设备，我希望使用有效身份接入，并按所属产品约定上报数据及命令执行结果，以便平台理解设备状态和行为。
- 作为获授权用户，我希望查询设备状态和历史数据、下发并跟踪命令、查看和处理告警，以便完成设备运营工作。

**阶段 3 · 通知模块**

- 作为租户管理员，我希望配置告警的 Webhook 接收端点并查询投递状态，以便把告警交付到本租户使用的外部系统。
- 作为外部接收系统，我希望收到可验证来源的告警通知，以便处理相关业务事件。
- 作为运维人员，我希望追踪通知投递尝试和结果，以便诊断和处理投递问题。

**阶段 4 · AI 模块**

- 当前没有已确认的 AI 用户用例。进入阶段 4 前须确定使用者、业务问题、可用数据和可量化收益。

## 6. 范围之外

- 阶段 2 IoT、阶段 3 通知和阶段 4 AI 的能力不属于当前阶段 1 交付范围；它们的路线方向不等于已批准或已实现的详细需求。
- 本 PRD 不替代阶段 1 管理模块 Spec；具体用户流程、接口契约、领域模型和验收标准以 Spec 为准。
- 尚未明确场景和收益目标的具体 AI 功能不进入当前交付承诺。
- 独立的 Nextboard 模板及其与 Roseiot 后端 API 的连接不属于本次 Roseiot 产品能力范围。
- 具体行业解决方案、计费与商业模式、服务等级承诺及渠道策略尚未确定，不在本次产品范围内。

## 7. 成功指标

以下为待建立基线和目标值的候选衡量方向，不构成已批准的量化承诺：

- 阶段 1：平台管理员和租户管理员能够完成其获授权的管理任务；受邀成员能完成账户激活；账户与租户访问按配置权限生效。
- 平台运营方能够完成租户建立和管理工作的比例与耗时。
- 租户能够完成设备接入、数据查看和设备操作闭环的比例与耗时。
- 告警从产生到相关人员获知和处理的比例与耗时。
- 租户及其活跃设备的持续使用情况。

指标定义、数据来源、基线、目标值和观测周期均待确认；需结合首批用户和代表性场景确定。

## 8. 风险与假设

- **已确认**：平台面向跨行业的 IoT 平台运营方与租户；核心产品目标是让他们在多租户平台管理设备、数据、操作与告警。
- **已确认**：能力按管理、IoT、通知、AI 的顺序分阶段规划；当前工程基线已完成，管理模块尚未实现。
- **已确认**：用户、租户和权限管理属于阶段 1 管理模块；之后规划 IoT、通知模块；AI 具体能力尚未定义。
- **已确认**：Nextboard 是独立模板，使用自身演示数据，不调用 Roseiot 后端 API。
- **待验证假设**：跨行业共性足以支撑统一产品能力；首批用户研究需要验证哪些流程和能力最有价值。
- **主要风险**：行业差异可能导致通用产品范围膨胀；如果首批场景、租户运营方式和成功指标不明确，阶段优先级及产品价值难以验证。
