# 初始化首位系统管理员

Flyway 在首次启动时创建 `default` tenant 和受保护的 `SYSTEM_ADMIN` 角色。平台不提供公开注册或初始化 API。部署负责人须在首次投入使用前，通过受控运维会话运行仓库中的一次性 SQL。

## 前置条件

- 应用已对目标 PostgreSQL 数据库完成 Flyway 迁移。
- 已通过应用选用的密码编码器，为一个强随机临时密码生成编码后的密码哈希。不要把明文密码写入 SQL、命令行参数、shell 历史或仓库文件。
- 运维操作者已通过独立安全渠道把临时密码交付给首位系统管理员。
- 使用拥有创建用户和写审计记录权限的数据库运维身份；不要把数据库管理员凭证交给应用用户。

## 执行

在受控终端打开 psql 会话，并关闭 psql 命令历史：

```bash
PSQL_HISTORY=/dev/null psql -X "$ROSEIOT_DATABASE_URL" -v ON_ERROR_STOP=1
```

在 psql 提示符中设置本次运行所需的三个变量，再执行脚本。密码哈希不是明文密码，但仍属于敏感凭证材料；避免录屏或记录终端会话：

```text
\prompt '登录邮箱: ' email
\prompt '显示名称: ' display_name
\prompt '临时密码的编码哈希: ' password_hash
\i scripts/bootstrap-system-admin.sql
\q
```

SQL 在一个事务中建立 `ACTIVE` 系统用户、`UserCredential`、`SYSTEM_ADMIN` 角色关联和首管 `AuditRecord`。凭证被标记为首次登录必须修改密码。SQL 只接受至少 40 个字符且采用编码器常见前缀格式的哈希值；不会生成默认凭证或接收明文密码。

脚本使用 PostgreSQL 事务级 advisory lock 串行化并发启动，并在锁内检查管理员角色是否已分配。成功执行后重放会失败；失败会回滚用户、凭证、角色关联和审计记录。不要手动删除管理员角色关联来重置引导流程。

## 权限目录

当前源码尚未定义系统权限目录，因此迁移会创建受保护的 `SYSTEM_ADMIN` 角色，但 `role_resource` 初始为空。后续管理模块切片需在源码定义权限标识后，通过新增迁移将其投影为 `BUTTON` 资源并关联到该角色。引导 SQL 不定义或修改权限。

## 验证与首次使用

成功执行时 psql 返回 `COMMIT`。部署人员应通过后续提供的认证流程验证登录，并确认系统要求更改临时密码；在认证接口交付前，此数据库初始化仅建立首管身份，不代表已经提供登录能力。任何失败都应保留错误信息供运维排查，但不得把密码哈希写入工单或日志。
