## 1. 文档目的

本文档维护 Roseiot **当前有效的产品需求总览**，帮助开发者和 Agent 理解产品要解决的问题、功能边界与核心业务规则。需求来源于已确认的[产品访谈决策日志](interview-decisions.md)，并随后续功能决策持续更新。

本文档不替代：

- [路线图](../roadmap.md)：建设顺序、阶段边界和候选功能；
- `docs/sdd/`：单个可交付切片的精确行为契约、验收标准和实施计划；
- `docs/adr/`：难以逆转且存在真实权衡的架构决定；
- [领域词汇](../../GLOSSARY.md)：统一领域语言。

当本文档与已批准 Spec 冲突时，不直接猜测优先级；应确认需求是否已变更，并同步修正文档。访谈日志保留历史，不因需求演进而改写。

## 2. 产品定位

Roseiot 是一个用于学习真实 IoT 场景、验证工程取舍并展示工程能力的多租户 IoT 平台后端。项目采用生产式设计纪律，但当前不宣称生产就绪，也不为未出现的客户、规模或合规要求提前建设。

### 2.1 目标用户

- **平台管理员**：创建、停用和恢复租户，执行受控平台运维。
- **租户管理员**：管理本租户成员、产品、设备、规则、通知端点和安全凭证。
- **租户成员**：在授权范围内查询设备数据、下发命令和处理告警。
- **设备**：通过独立机器凭证接入平台，上报数据并执行命令。

### 2.2 标准演示场景

一个租户创建“温湿度控制器”产品并注册模拟设备。设备上报温度、湿度、开关状态和固件版本；用户查询遥测与当前状态、下发开关命令；温度超过阈值时产生告警并投递 Webhook 通知。

### 2.3 当前目标

1. 完成租户、用户、产品、设备与凭证的安全管理闭环；
2. 通过最小物模型约束设备数据和命令；
3. 完成 MQTT 遥测上报、HTTP 查询、命令下发和实时反馈；
4. 完成阈值规则、告警和 Webhook 通知闭环；
5. 以测试、演示和可复现测量证明正确性与已知边界。

### 2.4 非目标

当前不建设复杂组织树、**租户自定义角色与权限编辑器**、用户组权限（ThingsBoard PE 风格）、计费、通用规则 DSL、工作流、批量作业、OTA、数字孪生、边缘计算、插件平台、微服务体系或 Kubernetes 平台。授权首版采用 **RBAC-0（仅内置角色与系统 permission 种子）**，见 [`docs/adr/2026-10-08-identity-user-rbac.md`](../adr/2026-10-08-identity-user-rbac.md)。候选能力及进入条件以[路线图](../roadmap.md#后续候选功能)为准。

## 3. 全局产品原则

| ID | 需求 |
| --- | --- |
| `PRD-001` | 所有租户资源必须具有明确租户归属，服务端从认证主体建立租户上下文，不信任客户端提交的租户身份。 |
| `PRD-002` | 对不存在和无权访问的租户资源采用不泄露资源存在性的响应；敏感信息不得进入错误、日志、审计或通知载荷。 |
| `PRD-003` | 内部 ID、业务标识符和显示名称相互分离；名称不参与身份判断，已投入使用的业务标识符不可修改或复用。 |
| `PRD-004` | 已产生业务历史的资源优先停用或退役，不通过物理删除、隐藏监听器或数据库级联重写历史。 |
| `PRD-005` | 时间统一保存为 UTC；需要区分设备观测时间、平台接收时间和处理时间，审计以平台时间为准。 |
| `PRD-006` | 所有重试、重复投递和并发修改必须有明确的幂等身份、版本检查或唯一约束，不宣称跨系统“恰好一次”。 |
| `PRD-007` | API、MQTT、WebSocket 和 Webhook 都必须定义失败语义、授权边界、资源限制和可追踪标识。 |
| `PRD-008` | 当前状态、历史事实和投递尝试分开保存；管理员不得通过普通 API 改写命令、告警、通知或审计历史。 |

完整理由与边界见访谈 Q1～Q506。

## 4. 功能需求

### 4.1 平台、租户与身份

| ID | 需求 |
| --- | --- |
| `IAM-001` | 首个默认平台管理员通过显式、一次性的安全引导创建；迁移脚本和仓库不得包含固定账号或密码。 |
| `IAM-002` | 只有平台管理员可创建、停用、恢复租户；首版不开放匿名注册、套餐或计费。 |
| `IAM-003` | 人类登录主体统一为 **User**：规范化电子邮箱全平台唯一、稳定内部 ID；`tenant_id` 为空表示**平台作用域用户**，非空表示**租户用户**且首版至多绑定一个租户。 |
| `IAM-004` | 授权采用 **RBAC**：首版仅 **内置角色**（平台 `PlatformOperator`、租户 `TenantAdmin` / `TenantMember`）及系统 seed 的 permission；不提供租户自定义角色 UI。同一 User 记录不能既为平台作用域又绑定租户（互斥）；平台与租户须为不同 User（不同邮箱）若需两种身份。 |
| `IAM-011` | 业务 API **默认拒绝**；访问租户资源须具备对应 **permission** 且租户上下文与 `User.tenant_id` 及资源归属一致（`PRD-001`）。平台 API 使用独立入口，平台用户默认 **不** 具备租户设备数据与设备凭证读取 permission（Q38）。 |
| `IAM-012` | 不使用 ThingsBoard 式 **Authority** 枚举表达业务权限；access token 携带 `ctx`（platform/tenant）、租户 ID（如适用）及 **授权修订版本**；permission 在请求边界求值。角色变更、主体停用与密码修改等须递增修订版本并撤销 refresh 会话（与 `IAM-007` 一致）。 |
| `IAM-005` | 支持成员邀请、接受、过期、撤销和重新邀请；邀请和账户恢复不得泄露账号是否存在。 |
| `IAM-006` | 成员移除采用停用而非删除；历史记录继续引用原身份，且不得停用或降级最后一名有效租户管理员。 |
| `IAM-007` | 首版使用邮箱和密码认证、短期访问令牌及服务端可撤销的刷新会话；密码修改、主体停用和安全事件可撤销会话。 |
| `IAM-008` | 登录、恢复、邀请和敏感操作具备限速、通用失败响应、令牌单次使用和安全通知；浏览器安全策略在对应 Spec 中明确。 |
| `IAM-009` | 租户停用是用户访问、设备认证、异步任务、实时订阅和外部投递的持续资格条件，各执行边界必须重新检查。 |
| `IAM-010` | 租户删除首版不提供即时级联删除；导出、保留、擦除和管理员恢复必须走独立、可审计流程。 |

来源：访谈 Q2、Q6、Q38～Q46、Q56～Q63、Q179～Q232、Q471～Q488、Q507～Q510；ADR [`2026-10-08-identity-user-rbac`](../adr/2026-10-08-identity-user-rbac.md)。

### 4.2 产品、设备与设备凭证

| ID | 需求 |
| --- | --- |
| `DEV-001` | 产品表示一类设备共享的能力契约，不表示 SKU、项目或运营分组。 |
| `DEV-002` | 一个设备必须且只能属于一个产品；首版不迁移产品，需变更时退役旧设备并创建新身份。 |
| `DEV-003` | 产品在租户内、设备在租户内分别使用唯一业务标识符；标识符稳定且不因显示名称修改而改变。 |
| `DEV-004` | 产品支持启用和停用；存在设备的产品不可物理删除，停用后禁止创建新设备但保留查询能力。 |
| `DEV-005` | 设备支持启用、禁用和退役；已签发凭证、接入或产生数据的设备不可物理删除，其标识符不得复用。 |
| `DEV-006` | 设备身份与秘密凭证分离。首版每台设备只维护一个有效 Token，支持签发、原子轮换、吊销和泄漏处置。 |
| `DEV-007` | 凭证只在创建或轮换成功时显示一次；数据库只保存适合校验的摘要，日志、审计和列表不得返回秘密。 |
| `DEV-008` | 设备禁用或退役立即使新认证失败并使既有会话失去业务资格；关联命令按明确原因结束。 |
| `DEV-009` | 同一设备逻辑上只允许一个有效 MQTT 会话；新连接替代旧连接，旧会话不得继续上报或接收命令。 |

来源：访谈 Q4～Q7、Q12～Q15、Q18～Q19、Q103～Q105、Q109～Q113、Q169～Q178。

### 4.3 物模型

| ID | 需求 |
| --- | --- |
| `TM-001` | 每个产品拥有一个当前有效的最小物模型，定义遥测、上报属性和命令；物模型不作为可独立复用或发布的首版资源。 |
| `TM-002` | 字段具有稳定标识符、显示名称、类型，并按需具有单位、必填、数值范围、精度或字符串长度约束。 |
| `TM-003` | 首版数据类型限定为 `boolean`、`integer`、`decimal` 和 `string`；不提前实现对象、数组、枚举 DSL 或事件模型。 |
| `TM-004` | 同一产品内标识符不得跨遥测、属性和命令类别复用；格式与保留字由阶段 2 Spec 固定。 |
| `TM-005` | 物模型投入使用后只允许兼容性新增和展示信息修改；已有字段的标识符、类型、单位和核心语义不可原地改变。 |
| `TM-006` | 字段停用后拒绝新数据但保留历史解释；新增字段立即对产品下设备生效，不引入逐设备模型版本。 |
| `TM-007` | 单条上报中出现未知字段、类型错误、非法 `null` 或越界值时整条拒绝，不提供部分成功。 |
| `TM-008` | 单位用于定义语义，不自动换算输入；必填表示消息类别中的契约，具体适用范围由 Spec 明确。 |

来源：访谈 Q8～Q10、Q25、Q64～Q72、Q101、Q109～Q111。

### 4.4 MQTT 接入、遥测与上报属性

| ID | 需求 |
| --- | --- |
| `TEL-001` | MQTT Broker 负责协议连接与基础认证，平台负责设备状态、Topic 授权、物模型校验和业务确认；Broker 不成为业务真相源。 |
| `TEL-002` | Topic 必须绑定已认证设备身份和消息类别，不能仅凭可猜测 Topic 获得其他设备的发布或订阅权限。 |
| `TEL-003` | 每条上报消息包含协议版本、稳定消息 ID 和单一消息类别；一条消息不得混合遥测与属性更新。 |
| `TEL-004` | 协议确认只表示传输层接收；业务接收结果明确区分已持久化、重复接受和拒绝原因。 |
| `TEL-005` | 遥测按字段拆为不可变数据点，保存设备观测时间和平台接收时间；缺少设备时间时使用接收时间作为观测时间。 |
| `TEL-006` | 同一设备的消息 ID 用于去重；重复消息返回一致业务结果，不重复写入、求值或通知。去重窗口与保留边界由 Spec 明确。 |
| `TEL-007` | 迟到遥测可以保存和查询，但不得无条件倒退当前状态或重写已经基于更新数据形成的业务事实。 |
| `TEL-008` | 上报属性只保存每个字段的当前值、观测时间和接收时间；以确定性的时间及消息顺序规则进行并发更新。 |
| `TEL-009` | 在线状态是平台推断值，不等于设备业务健康；维护连接状态、最后活动时间，并允许超时后判定离线。 |
| `TEL-010` | 默认不长期保存原始 MQTT Payload，只保存规范化数据、必要元数据和受控错误摘要。 |
| `TEL-011` | 为消息大小、字段数量、频率、连接和积压设置有界限制；过载时明确拒绝或降级，不建立无界内存队列。 |

来源：访谈 Q9～Q11、Q16～Q19、Q47～Q51、Q71、Q81～Q88、Q273～Q288、Q415～Q434。

### 4.5 遥测查询与数据生命周期

| ID | 需求 |
| --- | --- |
| `QRY-001` | 遥测查询必须限定租户、设备、字段和时间范围，使用半开时间区间并规定最大范围、字段数和页面大小。 |
| `QRY-002` | 数据按稳定复合键排序，使用不透明游标分页；游标绑定查询条件并能在并发写入时提供可解释的继续语义。 |
| `QRY-003` | 多字段查询按数据点返回，不承诺将不同时间的字段拼成同一行；默认不返回昂贵的精确总数。 |
| `QRY-004` | 数值表示、精度、序列化和比较规则必须在协议与数据库间一致，避免静默精度丢失。 |
| `QRY-005` | 遥测具有明确保留策略；到期表示可异步清理，不承诺瞬时删除，清理不得删除当前上报属性。 |
| `QRY-006` | 清理任务有界、可恢复并记录汇总结果，不为每条物理删除生成普通通知或逐条审计。 |

来源：访谈 Q73～Q80、Q435～Q454。

### 4.6 命令与实时反馈

| ID | 需求 |
| --- | --- |
| `CMD-001` | 命令是用户请求设备执行的一次受追踪动作，必须引用产品物模型中当前有效的命令定义并通过参数校验。 |
| `CMD-002` | 命令创建支持租户范围内幂等键；相同键与相同请求返回原命令，不同请求冲突。 |
| `CMD-003` | 命令状态统一为待发送、已发送、成功、失败、超时、取消；终局状态不可被迟到响应改写。 |
| `CMD-004` | 离线设备命令仅在有限有效期内持久等待；到期转为超时，不保留无限离线队列。 |
| `CMD-005` | 取消是竞争操作：仅未进入不可逆执行阶段的命令可取消；取消、下发、响应和超时须并发安全。 |
| `CMD-006` | 平台可以重试传输但不能假设设备执行幂等；命令携带稳定命令 ID，设备应据此去重。 |
| `CMD-007` | 设备响应必须匹配设备、命令、会话资格和响应结构；未知、伪造、重复或迟到响应不得改变历史。 |
| `CMD-008` | 平台不保证多个命令严格按创建顺序执行；调用方显式等待依赖命令终局。 |
| `CMD-009` | 命令结果始终可通过 HTTP 查询；WebSocket 仅提供实时提示，断线恢复依赖持久事件和重新查询。 |
| `CMD-010` | WebSocket 在连接、订阅和每次事件发送时检查授权与主体状态；订阅有界，慢消费者有明确背压和断开策略。 |

来源：访谈 Q20～Q27、Q52～Q53、Q289～Q304、Q357～Q374、Q471～Q488。

### 4.7 规则与告警

| ID | 需求 |
| --- | --- |
| `ALM-001` | 规则归属租户并绑定一个产品；首版只支持单字段阈值规则，不建设通用 DSL 或复杂事件处理。 |
| `ALM-002` | 规则只消费已校验、已提交的数据；迟到数据不得反向制造不符合当前事实的告警状态。 |
| `ALM-003` | 规则修订创建新修订语义，不原地改变历史求值解释；停用字段或规则会以明确原因结束相关活动告警。 |
| `ALM-004` | 同一规则、设备及告警条件在一次活动周期内只有一个活动告警；并发求值依靠持久唯一性和事务保护。 |
| `ALM-005` | 告警生命周期与确认状态分离；确认只表示人员已知悉，不表示异常已经恢复。 |
| `ALM-006` | 告警结束原因至少区分条件恢复、规则停用、规则修订、字段停用和设备退役，不把所有结束都标记为恢复。 |
| `ALM-007` | 规则求值使用有界、可恢复的持久任务；任务重试不得重复创建告警或通知。 |

来源：访谈 Q28～Q36、Q305～Q339、Q471～Q488。

### 4.8 通知与 Webhook

| ID | 需求 |
| --- | --- |
| `NTF-001` | 通知是由已提交业务事实产生的不可变事件；通知事实与面向单个端点的投递过程分离。 |
| `NTF-002` | 每个事件具有稳定 Event ID，每次独立投递具有 Delivery ID，每次网络尝试另有 Attempt 记录。 |
| `NTF-003` | 首个通知通道为本地可验证的 Webhook；结构化日志仅用于诊断，不算完整通知闭环。 |
| `NTF-004` | Webhook 事件信封包含版本、事件 ID、类型、发生时间、租户与必要资源引用；默认最小披露，不发送秘密或完整对象快照。 |
| `NTF-005` | Webhook 请求使用端点独立 Secret 签名，并包含时间戳及防重放信息；Secret 只显示一次且支持轮换与吊销。 |
| `NTF-006` | 端点创建、修改、启用和每次投递均执行 SSRF 防护，包括协议、DNS 解析后地址、重定向、超时和响应大小检查。 |
| `NTF-007` | 投递采用至少一次语义和有限指数退避；同一投递重试保持 Delivery ID，不保证不同事件严格有序。 |
| `NTF-008` | 终局失败记录不可改写；管理员重新投递时创建新的 Delivery ID，并关联原失败记录。 |
| `NTF-009` | 端点停用、租户停用或授权失效时，尚未执行的投递按明确原因终止，不继续盲目重试。 |

来源：访谈 Q36～Q37、Q54～Q55、Q175～Q188、Q233～Q244、Q323～Q356。

### 4.9 审计

| ID | 需求 |
| --- | --- |
| `AUD-001` | 安全、权限、凭证、生命周期和受控运维等关键操作形成结构化、不可由普通业务接口修改的审计记录。 |
| `AUD-002` | 审计至少记录事件类型、平台时间、主体、租户、资源、动作、结果、关联 ID 和安全筛选后的变化摘要。 |
| `AUD-003` | 审计与应用日志分离；不保存密码、Token、Webhook Secret、完整请求体或默认对象快照。 |
| `AUD-004` | 审计查询按租户授权、时间范围、事件类型、主体和资源过滤，并使用有界游标分页。 |
| `AUD-005` | 普通租户主体不能修改或删除审计记录；平台运维访问、数据导出和数据库修复同样必须留痕。 |
| `AUD-006` | 审计写入与关键业务变化具有明确一致性策略；不能静默丢失，也不能因辅助详情失败留下不可解释的半状态。 |

来源：访谈 Q40～Q46、Q97、Q166～Q168、Q455～Q470。

## 5. 接口与一致性要求

### 5.1 HTTP API

- 对外 API 使用显式版本前缀、稳定资源标识、统一错误信封和关联 ID。
- 创建接口定义幂等行为；修改接口使用版本或条件请求防止丢失更新。
- 列表采用稳定排序和不透明游标；过滤条件、上限和空结果语义必须明确。
- 请求拒绝未知或不可写字段；响应允许兼容新增字段，敏感响应默认 `no-store`。
- 对跨租户访问隐藏资源存在性；验证错误不得回显秘密或未脱敏载荷。

来源：访谈 Q91～Q100、Q375～Q394。

### 5.2 PostgreSQL

- 首版使用共享 Schema，并在所有租户资源表中显式保存租户 ID；平台级与租户级数据边界清晰。
- 主键、外键、唯一约束、检查约束和必要索引共同维护数据完整性，不能只依赖应用层约定。
- 跨表引用同时验证租户一致性；软删除不作为默认通用机制。
- 普通应用数据库身份与迁移身份分离；迁移前进兼容、可测试且从空库可重复执行。
- 长事务、锁顺序、批量大小和并发更新必须有界；查询计划与索引由真实查询和数据规模验证。

来源：访谈 Q123～Q126、Q156、Q159～Q168、Q258～Q272、Q395～Q434。

## 6. 非功能需求

### 6.1 安全

- 默认拒绝、最小权限、服务端租户上下文和持续资格检查；不依赖客户端隐藏控件实现授权。
- 密码和设备 Token 使用成熟哈希方案；必须恢复的 Webhook Secret 使用受控密钥加密，密钥不入库。
- 日志、指标、追踪、错误、审计、Webhook 和测试夹具均执行秘密与个人信息最小化。
- 每个涉及租户资源的切片至少验证合法访问、跨租户隐藏、角色拒绝、主体停用、并发状态变化和敏感信息不泄露。

### 6.2 可靠性

- 内部异步工作采用持久、有界任务，明确认领、租约、重试、退避、超时、终局失败和重启恢复。
- 外部副作用从已提交事实产生；数据库事务不跨网络调用，重试不会重写历史。
- 启动时无效关键配置直接失败；关闭时停止接收新工作并在有限时间内处理或安全释放已认领任务。
- 首版单应用实例；多实例、消息队列和分布式协调必须由实测问题触发独立 Spec。

### 6.3 可观测性与运维

- 使用结构化日志、统一关联 ID、最小必要指标，以及区分存活和就绪的健康检查。
- 健康端点不得泄露配置、凭证、内部地址或堆栈；管理端点必须受限。
- 数据库迁移、备份恢复、配置加载和部署均需可复现；首个部署目标是简单容器化单机方案。
- 只有现有日志和指标不足以定位跨边界问题时才引入分布式追踪。

### 6.4 性能与容量

- 在没有测量证据时选择简单、直接、依赖少的方案。
- 所有入口、查询、队列、批量和响应体必须有界，并提供可解释的拒绝或降级行为。
- 性能结论必须记录数据规模、消息频率、消息大小、并发、硬件、持续时间、分位延迟和错误率。
- 阶段 2 建立遥测容量基线，阶段 3 验证命令与 WebSocket 背压，阶段 4 验证规则与通知积压恢复。

来源：访谈 Q81～Q90、Q118～Q158、Q233～Q288、Q496～Q503。

## 8. 需求维护规则

1. 新功能讨论先确定用户、问题、范围、非目标和可观察结果。
2. 用户确认的访谈建议追加到[决策日志](interview-decisions.md)，不覆盖历史。
3. 改变当前有效产品行为时，同步修改本 PRD，并保留稳定需求 ID；废弃需求标注“已废弃”及取代者，不复用 ID。
4. 进入实现前，把相关 PRD 条目拆成 `docs/sdd/` 中可验收的 Spec；Spec 获批后再写 Plan。
5. 新术语同步维护 [GLOSSARY](../../GLOSSARY.md)；满足 ADR 条件的技术决定才写入 `docs/adr/`。
6. 每个 PRD 变更应能追溯到访谈问题、Issue、Spec 或 ADR 中至少一种来源。
