# Domain Docs

How the engineering skills should consume this repo's domain documentation.

## Before exploring, read these

- `GLOSSARY.md` at the repo root.
- Relevant ADRs in `docs/adr/`.

If these files do not exist, proceed without flagging their absence. Create them only when a term or decision needs to be recorded.

## Use the glossary's vocabulary

Use terms as defined in `GLOSSARY.md` in issue titles, design notes, hypotheses, and tests. If a needed concept is missing, check whether the project is using an existing term or whether a real domain gap needs to be resolved.

## Flag ADR conflicts

If a proposal contradicts an existing ADR, surface the conflict explicitly rather than silently overriding the decision.
