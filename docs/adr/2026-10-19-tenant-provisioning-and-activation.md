# 租户开通与启用

- **状态**：Accepted
- **日期**：2026-10-19

## 背景

每个可用客户租户必须至少有一名有效租户管理员。租户用户只能通过邀请加入，而邀请须由收件人接受并设置密码后才会激活用户。如果新租户创建后立即开放业务访问，系统会出现“可用但没有管理员”的时间窗口。

## 决策

- 客户租户创建后处于 `PENDING_SETUP`，不开放正常租户业务访问。
- 创建租户时，系统管理员配置该租户获准使用的资源集合，系统在同一租户初始化流程中创建受保护的 `TENANT_ADMIN` 角色，并通过 `role_resource` 关联该租户获准使用的全部租户管理权限标识。
- 系统管理员指定首位租户管理员并发送包含 `TENANT_ADMIN` 角色的一次性邮件邀请。首位管理员接受邀请、设置密码后，系统在一个原子流程中消耗邀请、建立或激活用户、关联 `TENANT_ADMIN` 角色并将租户状态改为 `ACTIVE`。
- 每个 `ACTIVE` 客户租户必须始终至少有一名有效且关联该租户 `TENANT_ADMIN` 的用户。删除、注销、停用用户或移除角色关联时，不得移除最后一名有效租户管理员；并发状态变更也必须维护此不变量。
- 首位管理员邀请过期或被撤销时，租户继续保持 `PENDING_SETUP`。系统管理员可以重新发送邀请或取消待启用租户。具体 API、失败恢复和清理规则由管理模块 Spec 定义。

## 后果

- 租户创建与租户可用状态分离，客户端不能访问尚未建立管理员的租户业务数据。
- 首次邀请接受流程必须同时完成用户准入、管理员角色关联和租户启用；任一步失败都不能留下部分启用状态。
- 每个客户租户需支持 `PENDING_SETUP`、`ACTIVE` 和 `DISABLED` 状态；状态转换和重复提交的 HTTP 契约由管理模块 Spec 定义。
