# ADR：租户模型与生命周期

- **状态**：Accepted — 现行决策
- **日期**：2026-10-10
- **关联需求**：`IAM-001`、`IAM-003`、`IAM-004`、`IAM-009`、`IAM-013`

## 决策

- Roseiot 固定采用多租户部署，不提供单租户模式分支或模式配置。数据库保留 slug 为 `default` 的平台租户；平台租户不能通过普通租户 API 创建、修改、停用或删除。
- 每个用户和客户业务数据都归属一个租户。平台用户绑定 `default`；客户用户绑定其客户租户。租户上下文必须来自认证主体或可信服务端上下文，调用方传入的租户 ID 不能替代隔离校验。
- 租户隔离覆盖所有租户拥有的数据。平台管理授权不自动构成跨租户访问客户数据的权限。
- 租户创建、内置角色/授权与初始邀请保持事务一致；失败时整体回滚。平台基础租户、资源目录和平台角色由 Flyway SQL 初始化；租户专属角色随租户实体创建时初始化，因为具体租户在数据库迁移执行时尚不存在。
- 租户停用会阻止成员访问和后续业务操作；执行边界必须检查租户状态。删除租户须遵守用户、设备和业务数据的生命周期约束。
- 租户邀请属于 `tenant` 能力，实体与表名为 `TenantInvitation` / `tenant_invitation`；邀请 token 只保存摘要，接受操作需要校验 token 及过期/消费状态。

## 后果

- 不再维护单租户与多租户两套行为、过滤器或配置。
- 租户隔离在数据查询、授权判断及异步/外部执行边界保持一致；`default` 租户只承担平台控制面身份与目录所有权。
- 客户内置角色需在租户创建事务内初始化，不能由静态 Flyway 行预先绑定到尚未创建的客户租户。
