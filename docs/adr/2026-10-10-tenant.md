# ADR：租户模型与生命周期

- **状态**：Accepted — 现行决策
- **日期**：2026-10-10
- **关联需求**：`IAM-001`、`IAM-003`、`IAM-004`、`IAM-009`、`IAM-013`

## 决策

- 系统固定采用多租户模型。租户使用数据库自增 `BIGINT id` 作为内部主键，并使用唯一 `code` 作为外部稳定标识；API 路径和响应使用 `code`，业务表关联内部 `id`。
- 平台保留租户使用 `id=1`、`code=default`，不能通过普通租户 API 创建、修改或停用。客户租户 code 使用 12 个随机字节生成的 16 字符 URL-safe 字符串，并由数据库唯一约束兜底；使用 JDK `SecureRandom` 和 Base64 URL 编码，不增加 NanoID 依赖。
- 用户和租户业务数据归属一个租户。租户上下文必须来自认证主体或可信服务端上下文，调用方传入的租户 ID 不能替代隔离校验。
- `Tenant.status` 使用 `ACTIVE` / `DISABLED` 表达生命周期，不再用可空时间字段编码停用状态。
- 租户隔离覆盖所有租户拥有的数据。平台管理授权不自动构成跨租户访问客户数据的权限。
- 平台保留租户和资源目录由 Flyway SQL 初始化，不预置角色。创建客户租户只创建租户记录；用户和角色由用户管理流程按需创建。
- 租户停用会阻止成员访问和后续业务操作；执行边界必须检查租户状态。删除租户须遵守用户、设备和业务数据的生命周期约束。

## 后果

- 不再维护单租户与多租户两套行为、过滤器或配置，也不依赖可变名称定位租户。
- 自增 ID 仅用于内部关联；对外使用的 code 与数据库顺序解耦。平台默认 code 固定为 `default`。
- 用户邀请流程当前不实现；首次用户创建与角色分配由后续用户管理入口负责。
