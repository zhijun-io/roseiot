# ADR：IAM 身份认证与授权

- **状态**：Accepted — 当前决策
- **日期**：2026-10-10
- **关联需求**：`IAM-001`～`IAM-016`

## 决策

- 人类身份与访问管理归 `io.roseiot.iam`。`UserCredential` 保存密码和密码重置状态；用户、角色、资源及用户角色关系归 IAM。当前不实现服务端用户会话或 refresh token；设备凭证属于未来设备能力。
- 原则上一个实体对应一个 Mapper、Service、Controller，遵守单一职责，避免重复编排层和无当前用例的抽象。密码操作由 `UserCredentialService` 负责，用户资料由 `UserService` 负责。
- 认证由 Spring Security 管理。`POST /login` 校验密码并返回短期 access JWT；JWT 有效期为 15 分钟，包含用户 ID（`sub`）和租户 ID（`tid`）。不提供刷新和服务端 logout 接口；客户端退出时清除本地令牌，令牌到期后重新登录。
- access JWT 不持久化。每个受保护请求加载当前用户、租户状态和权限；停用用户或租户会阻止后续请求。密码修改、密码重置及角色变化不撤销已签发 JWT，既有令牌最多可继续使用至其 15 分钟有效期结束。
- JWT 签发封装在 `JwtTokenFactory`。签名密钥来自外部配置。
- 路由直接使用复数资源路径，不添加 `/api`、`/noauth` 或 `/internal` 前缀。登录保留 `POST /login`；当前用户操作位于 `/me`。Spring Security 按具体资源配置认证边界。
- 授权键仅为活动 `ACTION.code`，代码中使用常量定义授权 code。角色关联 ACTION；父子资源层级仅用于导航，不隐含授权。
- 平台专属 ACTION 由 `ActionCode.PLATFORM_ONLY` 明确列出；客户租户角色不可分配这些操作。其它活动 ACTION 可分配给客户租户角色。
- `Resource.status` 使用 `ACTIVE` / `DISABLED` 表达资源是否可参与授权和展示。
- SQL 迁移初始化平台资源目录和平台内置角色，不创建函数或触发器。客户租户特有内置角色与授权在租户创建事务中初始化。
- 用户激活状态由 `User.status` 表达；目前不持久化激活码或激活时间，也不创建独立激活实体。

## 后果

- access JWT 是短期 bearer 凭证。用户权限变更不会即时撤销已签发 token；权限在 token 过期或重新登录后生效。密钥泄漏时通过轮换签名密钥使现存 token 失效。
- 密码重置和租户邀请使用一次性 token 作为资源标识；token 用后失效。
- 新增平台专属 ACTION 时，必须同步更新 `ActionCode.PLATFORM_ONLY` 并覆盖角色分配与授权查询测试。
- 激活凭证和流程尚未实现；后续需求获批后再决定是否需要独立实体。
