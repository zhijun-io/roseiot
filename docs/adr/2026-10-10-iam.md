# ADR：IAM 身份认证与授权

- **状态**：Accepted — 当前决策
- **日期**：2026-10-10
- **关联需求**：`IAM-001`～`IAM-016`

## 决策

- 人类身份与访问管理归 `io.roseiot.iam`。`UserCredential` 保存密码和密码重置状态；用户、角色、资源及用户角色关系归 IAM。当前不实现服务端用户会话或 refresh token；设备凭证属于未来设备能力。
- 原则上一个实体对应一个 Mapper、Service、Controller，遵守单一职责，避免重复编排层和无当前用例的抽象。密码操作由 `UserCredentialService` 负责，用户资料由 `UserService` 负责。
- 认证由 Spring Security 管理。`POST /api/login` 校验密码并返回短期 access JWT；JWT 有效期为 15 分钟，包含用户自增 ID（`sub`）和租户自增 ID（`tid`）。不提供刷新和服务端 logout 接口；客户端退出时清除本地令牌，令牌到期后重新登录。
- 密码使用 Spring delegating password encoder 写入带算法标识的 BCrypt 哈希；为兼容既有无前缀 BCrypt 哈希，验证时保留 BCrypt fallback。新密码按 UTF-8 编码限制为最多 72 字节，避免 BCrypt 超长输入截断。
- access JWT 不持久化。每个受保护请求加载当前用户、租户状态和权限；停用用户或租户会阻止后续请求。密码修改和密码重置不撤销已签发 JWT；角色或权限变更在后续请求加载当前权限时立即生效，但不使 JWT 本身失效。
- JWT 签发封装在 `JwtTokenFactory`。签名密钥来自外部配置。
- 所有 Roseiot HTTP 请求（包括 Actuator）都位于 `/api` 下。业务 Controller 显式映射该前缀，Actuator base path 为 `/api/actuator`。路由使用复数资源路径，不添加 `/noauth` 或 `/internal` 前缀。登录使用 `POST /api/login`；当前用户操作位于 `/api/me`。Spring Security 按具体资源配置认证边界。
- 授权键仅为活动 `ACTION.code`。授权 code 在权限检查、角色配置和查询中直接使用字符串，不维护集中常量类。角色关联 ACTION；父子资源层级仅用于导航，不隐含授权。
- 平台专属 ACTION 在角色分配查询中直接排除；客户租户角色不可分配这些操作。其它活动 ACTION 可分配给客户租户角色。
- `Resource.status` 使用 `ACTIVE` / `DISABLED` 表达资源是否可参与授权和展示。
- `User.status` 当前只包含 `ACTIVE` / `DISABLED`。Tenant、User、Resource 状态枚举各自归属实体，不合并成通用枚举。
- SQL 迁移初始化平台资源目录，不创建函数或触发器，也不预置角色。角色由后续用户管理流程按需创建；Role 不使用 code 或 `built_in` 标志。
- Tenant、User、Role、Resource 和 SystemSetting 的主键均为数据库自增 `BIGINT`。Tenant 另有唯一 `code`；其余对外资源使用自增 ID。UserRole 与 RoleResource 使用复合主键，Credential 以 user ID 为主键，不额外生成代理 ID。表名使用单数 `snake_case`；用户表命名为 PostgreSQL 保留字 `user`，DDL、SQL 和 ORM 映射统一使用双引号。数据库外键与复合唯一约束负责兜底关联存在性和租户归属，服务层仍校验业务规则并提供明确错误。
- 用户激活状态由 `User.status` 表达；目前不持久化激活码或激活时间，也不创建独立激活实体。

## 后果

- access JWT 是短期 bearer 凭证。每个请求都会加载当前授权，因此角色或权限变更影响后续请求，但不会撤销 JWT 的认证凭证；密码修改或重置也不会撤销现存 token。用户或租户停用会阻止后续请求。密钥泄漏时通过轮换签名密钥使现存 token 失效。
- 关系完整性由版本化迁移中的外键、复合唯一键和索引维护；新增关联时继续优先使用包含 `tenant_id` 的复合外键防止跨租户引用。
- V6 将用户表重命名为 `"user"`；该项目不需要支持旧应用版本并行运行。
- 密码重置使用一次性 token；token 用后失效。
- 新增或调整 ACTION code 时，必须同步维护资源 seed、授权检查和角色分配规则，并覆盖相关授权测试。
- 激活凭证和流程尚未实现；后续需求获批后再决定是否需要独立实体。
