# ADR：IAM 身份认证与授权

- **状态**：Accepted — 现行决策
- **日期**：2026-10-10；按 2026-10-10 用户确认整理
- **关联需求**：`IAM-001`～`IAM-016`

## 决策

- 人类身份与访问管理归 `io.roseiot.iam`。用户密码和密码重置状态归 `UserCredential`；用户、角色、资源、用户角色关系和用户会话分别由 IAM 持有。设备凭证属于未来设备能力，不放入人类用户凭证。
- 原则上每个实体对应一个 Mapper、Service、Controller，各层只处理持久化、实体业务和 HTTP 资源职责；遵守单一职责，不增加重复的编排层或通用抽象。密码操作由 `UserCredentialService` 和对应 Controller 负责，用户资料由 `UserService` 负责。
- 安全认证与授权统一由 Spring Security 管理。登录和 token 刷新由 `SecurityFilterChain` 中的过滤器处理：`POST /login` 使用密码凭证创建会话，`POST /token` 校验 refresh JWT 与数据库会话后轮换 token；两者不要求 access token。`DELETE /logout` 要求 Bearer access token；默认撤销当前会话，`?all=true` 撤销当前用户的全部会话。
- 其它业务路由按 `/{namespace}/{plural-resource}/...` 规划：`/api/**` 必须有 access-token 登录态；`/noauth/**` 无需 access-token 登录态，但仍校验端点所需的专用凭证；`/internal/**` 预留内部调用。
- `UserSession.tokenHash` 是 refresh JWT 原文的 SHA-256 摘要，不存 refresh token 原文。刷新时旧会话撤销并创建新会话；旧 token 重放按 family 撤销策略处理。
- JWT 的创建和校验统一封装在 `JwtTokenFactory`，包含 access token 和 refresh token。签名密钥来自外部配置；token 类型、声明和有效期由工厂统一处理。
- 授权键仅为活动 `ACTION.code`，代码中使用常量定义授权 code。角色关联 ACTION；父子资源层级仅用于导航，不隐含授权。
- `Resource.scope` 表达 ACTION 是否可授予客户租户角色：`TENANT` 可授予客户角色，`PLATFORM` 仅限平台受保护角色。该区分当前用于可分配 ACTION 列表和服务端授权约束。`BOTH` 当前没有内置资源使用，保留与否应由真实共享授权场景决定，不因此增加额外逻辑。
- SQL 迁移初始化平台资源目录和平台内置角色。SQL 不创建函数或触发器。客户租户特有的内置角色与授权在租户创建事务中初始化，随租户创建一同提交或回滚。
- IAM 会话实体和表名为 `UserSession` / `user_session`。会话、用户停用、角色变化和密码修改等状态按当前授权版本校验及会话撤销规则处理。
- 用户激活目前只通过 `User.status` 表达；当前不持久化激活码或激活时间，也不创建独立激活实体。实际激活流程获批后再确定是否需要独立实体。

## 后果

- `/noauth/**` 只表示认证方式不依赖 access token，不等于匿名执行或跳过 refresh/reset/invitation token 校验。
- 数据库只持有 refresh token 摘要，可按 session 查询并撤销；数据库泄漏不会直接暴露可重放的 refresh token。
- `Resource.scope` 是当前区分平台授权与租户授权的安全边界，不是菜单展示属性。新增 scope 值必须有明确使用场景并同步服务端校验与测试。
- 用户状态为 `PENDING_ACTIVATION`、`ACTIVE` 或 `DISABLED`；激活凭证和流程尚未实现，未来需求需单独建模。
