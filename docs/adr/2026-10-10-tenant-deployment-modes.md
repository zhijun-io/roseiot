# ADR：固定租户部署模式

- **状态**：Proposed — 等待租户部署模式 Spec 批准
- **日期**：2026-10-10
- **关联需求**：`IAM-013`、`PRD-001`
- **关联 Spec**：[租户部署模式（草案）](../sdd/2026-10-10-tenant-deployment-mode-spec.md)

## 背景

部署者需要预先确定数据库允许一个或多个租户，并确保系统运行后不能通过管理 API、配置刷新或普通重启配置切换这一模式。直接“关闭租户”会影响用户身份、RBAC、会话和租户资源边界；当前 IoT 业务需要租户用户身份来执行租户内操作。

## 决策

- 采用 `SINGLE_TENANT` 和 `MULTI_TENANT` 两种部署模式。单租户模式仍使用租户上下文、租户用户、租户成员管理和数据隔离，只将可创建的租户总数限制为一个；多租户模式保持现有行为。
- 两种模式共用 schema、认证、授权和 SQL 租户隔离逻辑，不为单租户模式跳过租户边界校验。
- 部署配置在首次初始化时明确提供，并将模式记录持久化在数据库。应用不提供修改记录的 API；配置与已记录模式不一致时启动失败。
- 模式切换和相应数据转换不属于普通配置更新。未来如需切换，必须单独定义、批准并执行迁移方案。

## 后果

- 单租户部署仍可使用现有流程创建唯一租户、邀请首位管理员并使用租户业务；再次创建租户被拒绝。
- 系统使用同一数据结构和授权实现，减少单租户/多租户分叉及隔离测试差异。
- 部署、备份和恢复流程必须保留相同的模式配置；错配时实例不可用，避免静默改变数据语义。
- 首次初始化配置、数据库持久化和单租户并发创建约束由租户部署模式 Spec 定义；转换操作仍需未来独立设计。
