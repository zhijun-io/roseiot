# 权限目录的代码定义与数据库投影

- **状态**：Accepted
- **日期**：2026-10-19

## 背景

服务端授权依赖稳定权限标识，而管理端又需要可查询、可分配的资源记录。若代码与数据库各自维护任意权限标识，二者可能漂移并造成未受保护或无法授予的操作。

## 决策

- 每个可授权权限标识在源码中定义，并由受保护的 API 操作引用；API 授权判断使用权限标识，不使用角色名称、菜单名称或客户端可见状态。
- 每个可分配权限标识格式为 `模块:资源:动作`，并对应一个 `BUTTON` 资源记录。Flyway migration 为内置资源目录及受保护的 `SYSTEM_ADMIN` 角色建立初始记录与关联；创建客户租户时初始化受保护的 `TENANT_ADMIN` 角色，并在 `role_resource` 中关联该租户通过 `tenant_resource` 获准使用的全部租户管理权限标识。`SYSTEM_ADMIN` 关联系统管理操作所需的全部权限标识；两个内置角色及其权限关联均不可经管理 API 修改。其他角色只能关联已定义且该租户获准使用的权限标识。
- 引导 SQL 仅把首位管理员关联至内置角色，不定义新的权限标识或内置资源。
- 未知或已退役的权限标识不得被分配或授权。数据库目录与源码定义的同步规则必须通过迁移或验证测试检查。

## 后果

- 增加新的授权操作需要同步代码中的权限定义与相应数据库资源投影。
- 数据库 API 不能创建任意字符串权限；执行时可验证每个授权关联指向已知 BUTTON 权限，并符合 `模块:资源:动作` 格式。
- 内置角色与权限目录由迁移及租户创建流程管理；用户创建的普通角色关联由业务 API 管理。
