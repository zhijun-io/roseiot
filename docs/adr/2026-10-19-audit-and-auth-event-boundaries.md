# 审计记录与认证事件的独立边界

- **状态**：Accepted
- **日期**：2026-10-19

## 背景

管理审计关注已发生操作的操作者、目标和结果；认证事件还需覆盖尚未建立用户身份的登录失败。两类记录的必填字段、访问控制和生命周期不同。

## 决策

- `AuditRecord` 与 `AuthEvent` 是独立领域模型和查询资源。认证事件可以没有用户主体；一条认证事件可无关联审计记录，也可通过关联 ID 与多条审计记录相关联，不建立必需的一对多外键。
- 审计记录由明确配置的 AOP 用例或显式审计 Service 发布；同一用例只能走一种路径。切面无法可靠获得上下文的生命周期事件由服务显式记录。首管引导 SQL 在创建事务中直接写入引导审计记录。
- 认证事件只由认证流程显式调用 AuthEvent Service 发布，不由审计切面代写。
- 两类记录均异步处理并持久化，但待处理事件必须可靠登记、支持重试和幂等，不能依赖进程内易丢失的异步队列。审计和认证事件各自独立处理；不预建通用事件平台。
- 两类记录均不得包含密码、原始 token、MFA/客户端秘密或未经筛选的敏感请求内容；查询分别按对应权限标识授权，并按记录所属租户和操作者可访问的租户边界过滤。

## 后果

- 业务事务与事件登记之间必须具备可靠性保障；具体存储和调度机制由实现计划结合当前规模选定。
- 查询可能存在短暂最终一致性延迟，客户端和运维流程需接受该延迟。
- AuthEvent 的安全失败记录能表达未知邮箱等没有 `User` 关联的尝试，而 AuditRecord 保持对已认证操作审计的语义。
