# 受控的平台与租户账户创建

- **状态**：Accepted
- **日期**：2026-10-19

## 背景

平台不开放公开自助注册。首个平台管理员必须在尚无管理账户时受控建立；之后的平台用户和客户租户用户应通过可验证邮箱控制权的流程加入。

## 决策

- 不提供公开注册入口，也不提供 `/api/setup` 或其他公开的首管初始化 API。
- `default` tenant 由 Flyway 初始化。首个平台管理员由受控、一次性的运维 SQL 建立，并关联受保护的内置 `SYSTEM_ADMIN` 角色。引导 SQL 不作为 Flyway migration，不包含固定默认凭证；必须防止重放和并发重复创建，并在同一事务内创建所需身份关联与引导审计记录。
- 首管使用临时密码首次登录后必须修改密码；修改前只允许改密及撤销当前会话。
- 之后的所有平台用户和租户用户均通过相应 tenant 下的邀请流程创建，不设专用平台管理员邀请接口。每份邀请都发送邮件；有效的一次性限时链接证明对目标邮箱的控制权，接受邀请时必须设置密码后才激活账户。
- 邀请可以不分配角色，也可以分配当前 tenant 内一个或多个角色。邀请不直接分配资源或权限标识。无角色用户可登录，但仅能访问 `/api/me/**` 和明确开放的公开接口；获授权的管理员之后可以分配角色。
- 重发邀请使先前 token 立即失效；邀请链接不可重复使用。角色分配和租户归属由服务端校验。

## 后果

- 初始平台账户的建立需要部署运维步骤及安全的临时密码哈希生成方式。
- 账户准入依赖邮件投递及 token 生命周期管理，相关流程须有可重试的邮件处理和明确状态转换。
- 邀请与角色权限解耦，账户激活不代表获得管理权限。
